# AI 接力启动包（怎么让另一个 AI 具备本项目能力）

> 编号 HANDOVER-ASTRON-AI-003 · 建立 2026-11-02
> **用途**：你要换 AI 干活时，照本文给文件 + 贴提示词，新 AI 就能接着干，不用重新摸索一遍。
> **核心原则**：给 AI 的不是"一堆文档"，而是 **3 样东西**：① 一份能自检的启动提示词 ② 最小必要文件 ③ 一个真实任务。文件给多了反而淹没重点。

---

## 一、先搞清楚：这个项目的"能力"到底是什么

新 AI 最容易误判的地方。**能力不在那 92 条流程里**（它们是验收用例，且用户明确「不迁移成品」），能力在下面**四样**：

| 资产 | 载体 | 值钱在哪 |
| --- | --- | --- |
| **① 规格 DSL 规范** ★ | `docs/流程规格DSL.md` | 怎么写 spec（结构 / `$p:`·`$变量`·拼接 / `need_parse` 必须 `$json:` / 3 个特殊参数 / 7 个坑）。**没有它，AI 只能靠猜** |
| **② 生成器** | `scripts/flow_generator.py` | spec → 平台节点树（`inputList`/`outputList`/`advanced`/`exception` 那一大坨），含路径规范化、`$p:` 烘焙、严格校验 |
| **③ 能力白名单 + 雷区清单** | `coverage_report.py`、`atom_impl_check.py`、`待办清单.md` §4、`平台缺陷清单.md`、`repro/` | 346 个原子哪些真能用、39 个"字典有实现无"、25 个卡凭据；15 条平台缺陷 + 11 个已知坑 |
| **④ 交付链路** | `publish_flow.py`、`ai_flow.py` | 落库 → 本地真跑 → 发布 vN → 登记 openapi → `execute-async`，全链路已实测跑通 |

**换句话说**：这个项目沉淀的是「**把人话变成能在 Astron RPA 上真跑起来的流程**」这项本事 + 一张平台坑图。**本事可以搬到任何环境、任何 AI；84 条成品流程不用搬。**

## 二、启动提示词（**直接复制粘贴给新 AI**）

```
你是接手「星辰开源 · AI 操作 RPA」项目的 AI。项目在 <项目路径>。
请严格按顺序做三件事，不许跳步：

【第 1 步】读文件
- 必读：docs/交接清单.md（全部）
- 必读：docs/待办清单.md 的 §0.0「项目定位」、§0.1「能用到什么程度」
- 写流程时必读：docs/流程规格DSL.md（逐节看，别跳——这是能力内核）
- 发布/调接口时再读：docs/开发文档-AI操作RPA-OpenAPI集成.md

【第 2 步】回答我四个问题，证明你真读懂了
1. 这个项目要"迁移"的到底是什么？哪些东西不用迁？
2. flows/ 里那 92 条流程是什么性质？为什么现在不再扩充了？
3. 新增一条流程之前，我必须先给你什么？
4. 本地真跑 SUCCESS，能证明流程做成了吗？为什么？

【第 3 步】答完就停手
不要写代码、不要建流程、不要跑发布。等我给一个真实业务场景，你再出方案。

【红线（违反任何一条即为做错）】
1. 不许新增没有真实业务场景的测试流程（默认参数指向 demo/ 的一律不许）
2. 不许把 COMPLETED / "运行成功" 当成成功，必须核对产出文件内容或副作用
3. 不许硬编码 robotId，一律用 --robot-name 按名字查找或新建
4. 发布是不可逆动作，必须先给我「机器人名 / 当前版本 / 目标版本」清单，我确认后才执行
5. 改流程后先确认设计器里旧标签已关闭，再落库；否则旧标签保存会把你的修改静默覆盖
6. 平台参数表可能残留历史测试值，跑失败先查 c_param 是否与规格一致
```

> 这段提示词的作用不是"教"新 AI，而是**逼它自证读懂了**。第 2 步三个问题答不上来的，说明它没读，直接换。

## 三、必须给的文件（按重要性排序）

> **给的是「能力」不是「成品」**：`flows/` 那 92 条已生成流程**不用迁**（用户明确「已生成流程不迁移，迁移的是能力」）。真正要带的是下面这些。

| 给 | 文件 / 目录 | 为什么 | 怎么给 |
| --- | --- | --- | --- |
| ① | `docs/交接清单.md` | 技术事实 + 红线，唯一必读入口 | git 里有，直接 clone |
| ② | `docs/待办清单.md` | §0.0 项目定位、§0.1 能用到什么程度、§4 坑表 | git 里有 |
| ③ | **`docs/流程规格DSL.md`** ★ | **能力内核**：怎么写 spec（结构/引用语法/3 个特殊参数/7 个坑）。**没有它，AI 只能靠猜** | git 里有 |
| ④ | `scripts/`（整个目录） | 干活的手：`capability_bootstrap.py` 验收、`ai_flow.py` 落库真跑、`flow_generator.py` 生成器、`publish_flow.py` 发布、`spec_lint.py` 校验、`atom_catalog.py` 查原子 | git 里有 |
| ⑤ | **`rpa_config.json`** | **不在 git 里**！含服务器地址 / API Key / 账号。不给就等于没手 | 手工拷，或 `python scripts/handover_export.py` 打包 |
| ⑥ | `docs/开发文档-AI操作RPA-OpenAPI集成.md` | 发布五步、openapi 登记、`execute-async` 的字段与坑 | git 里有 |
| ⑦ | `docs/平台缺陷清单.md` + `docs/repro/` | 15 条缺陷实测可复现，防重踩 | git 里有 |
| ⑧ | `flows/` 里**挑 2–3 条** | **只当格式参考**（看 spec 长什么样），不是让它接着造 | 挑 `Word转PDF小流程.json`、`文件按扩展名归档小流程.json` |

> ✅ **换机器不用改流程（2026-11-03 已解决）**：`flows/*.json` 里的路径默认值一律写成
> `${PROJECT_ROOT}/demo/...`，由 `flow_generator.load_spec()` 在发布时替换成本机仓库根 ——
> clone 到 `E:\work\AI-astron-rpa`，发布出来的参数就是 `E:\work\AI-astron-rpa\demo\...`。
> **不要**把它改成相对路径（`demo/订单.xlsx`）：引擎执行前会 `os.chdir(%APPDATA%\astron\<project_id>)`
> 这个编译缓存目录，相对路径必然找不到文件。
> 万一遇到历史规格残留旧机器路径：`python scripts/port_paths.py --write` 一键迁移；
> 运行时兜底还有 `nl_params.rebase_paths()`（按文件名在项目里唯一找回）。

### 建议**别给**的（给了有害）

| 别给 | 原因 |
| --- | --- |
| `flows/` 全部 92 条 | 用户明确不迁移成品；全给会让新 AI 以为"接着造流程"是正事 |
| `docs/reviews/`（202 份评审单） | 早期批量产物，口径已过时；**2026-11-03 起已不入库** |
| `demo/` 测试数据 | 会让新 AI 以为这些路径就是业务路径 |
| 旧对话记录 / 全部历史文档 | 太长，读不完就凭想象开工，比不读更糟 |

## 四、环境准备与**能力验收**（新机器，6 步）

```bash
# 1. 确认 Python（两选一，推荐设计器自带的，与引擎版本一致）
#    %APPDATA%/astron-rpa/python_core/python.exe   或   C:\Python314\python.exe

# 2. 装 Astron RPA 设计器，登录服务端并「连一次」（生成 SESSION cookie，脚本全靠它）

# 3. 把 rpa_config.json 放到项目根目录（不在 git 里，必须单独拷）
#    或：python scripts/handover_export.py --check --src <U盘>/handover

# 4. 坑 118：先建这个目录，否则引擎启动会报错
mkdir -p "$APPDATA/astron-rpa/astron"

# 5. 体检
python scripts/doctor.py
python scripts/publish_flow.py --list      # 能看到机器人列表 = 平台通

# 6. ★ 能力验收（一条命令验 7 项，这是"能力迁移成功"的客观标准）
python scripts/capability_bootstrap.py
python scripts/capability_bootstrap.py --live   # 再加端到端：真落库 + 真跑（会建一个自检机器人，验完可删）
```

**验收标准**：
- `7/7 通过` = 能力完整（配置/会话/平台/原子字典/生成器/引擎实现全部就位）
- `8/8 通过` = 连端到端都通（真建机器人 + 真跑 SUCCESS）
- 任何 ❌ → 先修环境，**别急着写流程**。缺 2/3/4 项基本是 `rpa_config.json` 没放对。

> 2026-11-02 在本机实测：**7/7、加 `--live` 8/8**（生成 3 节点最小流程 → 落库 → 真跑 SUCCESS 2.8s）。

## 五、怎么判断新 AI 是否跑偏（5 个红灯信号）

出现任意一条，立刻打断它：

| 红灯 | 说明 |
| --- | --- |
| 🚩「我先把剩下 9 条未落库流程补完」 | 又在扩测试集。**这些流程没有业务价值，不该补** |
| 🚩「覆盖率提升到 X%」当成果汇报 | 覆盖率是门槛不是成果 |
| 🚩「执行返回 COMPLETED，所以成功了」 | 典型假成功。必须看产出文件 |
| 🚩「我帮你设计一个 XX 场景的流程」 | 自己在编需求。**需求只能来自你** |
| 🚩 直接写 `robotId = 2116...` | 硬编码旧 id，换机器必挂 |
