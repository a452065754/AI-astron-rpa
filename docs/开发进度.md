11. **原子字典以实时为准**：docs 早期写「358 原子」，2026-10-30 实测 `c_atom_meta_new` 为 **345** 条；生成器改为实时拉取并落 `docs/atom_dict_cache.json`，不再硬编码数量。

13. **元素引用格式与「按 robot 隔离」**：真实流程里元素参数是 `{"type":"element","value":"元素名","data":"element_id"}`（92 个流程 758 处引用、178 个去重 id 全部命中 `c_element.element_id`，**`data` 就是 element_id，不是自增 `id`**）。但 `c_element` 同一 element_id 会按 `robot_id` 复制多行 —— 给某个 robot 生成流程时只能引用它名下的元素，跨 robot 借用会在运行时解析不到。目标 robot `2065231113695461380` 名下只有 12 个元素且全为 web（京东那批已失效），这是严格档 47/66 的唯一原因。
14. **`c_element.element_data` 的 `path` 不总是 dict**：web/uia 是 dict（含 checkType/pathDirs/xpath），个别批量/图像元素是 **list**；解析前必须 `isinstance(path, dict)` 兜底，否则 `AttributeError: 'list' object has no attribute 'get'`。
15. **关键词意图匹配会互相抢**：「把订单表导成新文件」含"文件"二字，若先判文件模板就会错配；`intent_match` 必须让 Excel 类关键词优先，或直接换成 LLM 语义匹配。
16. **`/openapi.json` 与 `/docs` 对 API Key 返回 401**（未在白名单），无法枚举 openapi-service 路由；只能用已知端点试探。这也印证 API Key 只能读+执行，不能建流程。
17. **可选参数不能填 `""`**：`inputList` 里每个 schema 参数都得给值，但可选参数若一律填空串，Bool 参数（`simulate_flag`/`scroll_into_center`）和枚举参数（`button_type`/`click_type`）会被运行时错误强转。必须用 schema 的真实 `default`（`_default_for`：default > options[0] > types 兜底）。实测 `BrowserElement.click` 的 `simulate_flag` 从 `''` 修成 `False`、`scroll_into_center` 修成 `True`。
18. **网页原子必须串在 `browser_open` 后面**：`BrowserElement.*` 的 `browser_obj` 是 Browser 类型，必须引用 `BrowserSoftware.browser_open` 的输出（输出 key=`web_open`，变量名可自定义如 `web`）。单独生成一个 click 节点结构合法但跑不了 —— 用模板的 `$web` 变量连线解决。
19. **落库字段与接口的三个坑**：①保存字段是 **`processJson`（JSON 字符串）**，不是 `process_content`；②流程必须先 `/process/create`，否则「流程数据不存在」；③`/process/process-json` 返回的 `data` **直接是字符串**（不是对象）。
20. **设计器列表字段叫 `robotName`**（不是 `name`）：按 `name` 匹配永远为 None，会重复创建机器人。同名流程重名会报 `600000 已存在同名的子流程名称`。
21. **`/process/name` 不是列表接口**：它返回「下一个建议流程名」（字符串）。要列流程用 `/process/all-data`。
22. **`c_process` 按 `robot_version` 分行**：v0=设计稿（save 固定写 0），发布复制到 v1 → 同一 `process_id` 有多行，**不是重复数据**。
23. **发布必须带 `version`**：`/robot-version/publish` 的 `version` 需大于最新版本（首次=1），否则报「版本号错误」。且**发布机器人 ≠ 进 openapi 列表**（`openai_workflows` 无服务端写入代码）。
24. **「主流程」是用户验收的唯一入口**：`/robot-design/create` 会自动建一条空「主流程」，**设计器点「编辑」默认打开的就是它**。把节点写进自己新建的子流程 → 用户看到主流程空白，以为生成失败。正确做法：`publish_flow.py --main`（从 `/process/all-data` 找 `processName=主流程` 的 id 再 save）。
25. **模板里的路径必须真实存在**：流程在**客户端本机**执行，`C:\订单.xlsx` 这种占位路径会让流程第一步就抛「找不到文件」（`Excel.open_excel`、`File.file_read` 都先 `os.path.exists` 检查）。演示数据统一放 `demo/`，模板默认路径指向那里。
26. **运行时参数陷阱（schema 校验查不出）**：①`Excel.read_excel.read_range` 是**枚举** `cell/row/column/area/all`，填 `"A1:Z1000"` → `NotImplementedError`；②`Excel.create_excel` 内部 `file_name += ".xlsx"`，传 `"导出结果.xlsx"` 会变 `导出结果.xlsx.xlsx`；③`Excel.save_excel` 在 `save_type=save` 时**忽略** `file_path/file_name`（只有另存为才用）；④直接调原子函数时枚举必须传枚举成员（引擎 `_recursive_convert_params` 会自动转，手写脚本不会）。→ 用 `scripts/verify_atoms_live.py` 真机预演。
27. **`Excel.close_excel` 参数名是 `save_type_one`**（不是 `save_type`），传错报 `unexpected keyword argument`。
28. **执行引擎退出码不可信**：引擎结束时 `kill_proc_tree(os.getpid())` 自杀，退出码是随机的（实测常见 15）。**唯一判据是日志里的 `ExecuteStatus.SUCCESS / FAIL`**（`logs/executor-*.log`）。写自动化时若按 `returncode==0` 判断会全部误判为失败。
29. **无 UI 执行的前提是设计器在运行**：`astronverse.executor` 不直连 `.130`，它打 `http://127.0.0.1:13159`（客户端本地网关），由网关带会话转发。设计器没开 → 网关未监听 → 执行必失败。`run_flow_local.py` 已内置该检查并给出人话提示。
30. **子流程默认不执行**：引擎只跑主流程（`Config.main_process_name="主流程"`）；子流程必须被调用。要单独跑某条子流程用 `--process_id`，此时它被编译成 `main.py`。
31. **`save_excel(close_flag=True)` 只关结果表**：源表不会关，Excel 进程与 `~$xxx.xlsx` 锁文件会残留（实测文件被占用到 `mv` 都失败）。Excel 类流程必须显式补 `Excel.close_excel(close_flag... save_type_one="abort")` 关源表，且用 `abort` 避免反写源文件。
32. **引擎编译时把路径反斜杠写成 `//`**（`F:\a\b` → `F://a//b`），Windows 能正常解析，但 UNC 路径 `\\host\share` 要多留意；本地执行验证时不要被这个表象误导成「路径错了」。
33. **`publish_flow` 的函数签名是 `(cookie, robot_id, process_id)`**，直接 import 调用时容易把 cookie 和 robot_id 传反，报「用户信息获取失败」（code 600000）。
34. **`RobotVersion.online` 是 Integer 0/1，不是布尔**：发布时传 `online: true` → `500002 请求参数解析失败`（Jackson 转 Integer 失败），且错误信息完全不提字段名，极难定位。要看 `RobotVersion.java` 实体类型而不是凭直觉传 bool。
35. **进 openapi 可执行列表靠 `POST /api/rpa-openapi/workflows/upsert`**（会话鉴权，body = `WorkflowBase`），**不是** `robot-version/publish`。`parameters` 必须是 **JSON 字符串**（`"[]"`）不是数组；`status=1` 才启用。已封装 `publish_flow.upsert_openapi_workflow()`。
36. **openapi 执行的是「已发布版本快照」，不是设计稿 v0**：主流程 v1 是空数组（`[]`，2 字节），`execute-async` 返回 `COMPLETED / 运行成功`、4 秒结束、**零副作用**。改完流程必须重新发布版本，否则 openapi 还在跑旧快照。
37. **`COMPLETED` ≠ 业务做成**：必须核对副作用（文件是否变化、内容是否正确）。实测 `导出结果.xlsx` 被「成功」重写，但里面是**空表**（A1:A1 无数据）—— 模板只 read 没 write。判定成功要「状态 + 产出」双证。
38. **`/robot-version/latest-info` 返回的是「下一个可用版本号」**（发布 v4 后返回 5），不是最新已发布版本。发布时直接用它，遇到「版本号错误」再 +1 重试（`publish_auto` 已实现）。
39. **`RobotVersion.online` 服务端会忽略**：publish 传 `online=1`，DB 里 v2~v5 仍是 0，但不影响 openapi 执行。别拿它当开关。
40. **`Excel.write_excel` 不存在**：358 个原子字典里没有这个 key，写数据用 `Excel.edit_excel`（`edit_range="area"` + `start_col`/`start_row` + `value`）。`value` **必须是二维列表**，传一维会报类型错。报「原子不存在」时先查字典，别凭直觉命名。
41. **`read_excel(read_range="all")` 返回「行×列」二维列表**，正好是 `edit_excel(edit_range="area")` 的入参格式 —— 读→写可以零转换直连，不需要自己 reshape。
42. **`workflows/upsert` 的 `parameters` 不登记 → 带参调用 403**：报错是 `Arguments do not match the tool input schema`，完全看不出是「参数表没登记」。必须从 `POST /api/robot/param/all {robotId, processId}` 读出真实参数（`varDirection/varName/varType/varValue/varDescribe`）序列化后填进去。
43. **失败原因在 `robot_execute_record.execute_log`，且是 JSON 套 JSON + 中文双重转义**：正则提 `"msg_str"` 后要**连续 `json.loads` 三次**才能还原成可读中文（只解一次会得到 `\u` 转义串，两次仍有残留）。已封装 `publish_flow.get_last_execute_error()`。
44. **`c_param` 的 `processId` 与 `moduleId` 不能同时为空**：`CParamDto` 必填 `varDirection/varName/varType/robotId`，且必须挂在某个流程或模块下，否则建参数报错。
45. **发布（publish）会改机器人名**：`robot-version/publish` 的 `name` 会写成机器人的 `robotName`。发布后机器人名=流程名（原「AI生成流程_测试」现叫「Excel订单表导出小流程」），别再按旧名找。
46. **headless 下 `127.0.0.1` 页面不可达**：沙箱/服务端执行器与用户机器不在同一网络命名空间，`http://127.0.0.1:8899` 打不开（用户浏览器也打不开）。web 演示页改到 `.130` 上 `python3 -m http.server 8899` 托管。
47. **中文文件名 URL 编码不一致 → 「未找到执行上下文」**：元素 `path.url` 是 URL 编码串、实际标签页 URL 是解码串，匹配不上时扩展拿不到 content-script 上下文。用 ASCII 文件名（`test.html`）规避。
48. **`ServerDb.sql_exec` 用 `json.dumps` 默认转义中文/反斜杠**：写含中文或 `\` 的字段会被 mysql 吞反斜杠（`\u8f93`→`u8f93`）。写 `c_element.element_data` 必须用**十六进制字面量 `X'..'`**，彻底免转义（并加 `--default-character-set=utf8mb4`）。
49. **`c_element` 按 robot 隔离**：`strict=True` 只认目标 robot 名下元素，新机器人要跑元素流程必须先把元素复制过去；复制后 **MD5 必须与源一致**，长度差 2 字节就是转义坏了。
50. **浏览器扩展需要页面上下文**：`BrowserElement.click` 走扩展 `checkElement`，要求目标标签页有 content-script 上下文；`checkType=onlyPosition` 可免图片校验，但页面必须真正加载完、URL 与元素 `path.url` 一致。
51. **直接调原子要转枚举**：schema 的 `types`（如 `CaseChangeType`/`MathOperatorType`/`TimeFormatType`）指向**同模块**的枚举类；传字符串会报 `'str' object has no attribute 'value'`，必须先转成枚举成员。
52. **`src` 里的类名带 `()`**：`astronverse.system.process.Process().get_pid`，解析时 `rsplit(".",2)` 得到 `Process()`，要 `replace("()","")` 才能 `getattr`，否则 `AttributeError`。
53. **`Network.http_request` 响应中文乱码**：atom 未按 UTF-8 解码响应，中文返回 latin-1 乱码（请求本身成功，需自行 `.encode('latin-1').decode('utf-8')` 修正）。
54. **`System.get_pid` 要完整进程名**：`chrome` → `[]`，`chrome.exe` → PID 列表（`search_type=exact` 按全名匹配）。
55. **没有「PDF 转 Docx」原子**：358 个原子里不存在直接转换。只能组合 `PDF.convert_pdf_to_img` → `Docx.create_docx` → `Docx.insert_img`×N → `Docx.save_docx`，产出是**图片版 Word**（版式保真、文字不可编辑）。
56. **`PDF.convert_img_to_pdf` 有实现 bug**：`astronverse/pdf/__init__.py` 的 `_handle_files_input()` **漏了 return**，恒返回 `None` → 任何调用都报「图片文件列表不能为空」。此原子当前完全不可用。
57. **`OpenApi.common_ocr` 503 的真因是「讯飞密钥为空」，不是「没部署 ai-service」**：`ai-service` 在跑，它内部调讯飞云 `https://api.xf-yun.com/v1/private/sf8e6aca1`，而 `XFYUN_API_KEY` / `XFYUN_API_SECRET` / `XFYUN_APP_ID` **三个环境变量全为空** → 讯飞 401 → 网关包成 503。**替代方案**：Windows 自带 `Windows.Media.Ocr`（离线、免费、无密钥，`scripts/win_ocr.ps1`）。
58. **Word 自带 PDF Reflow 不能用于扫描件**：`Docx.open_docx` 直接打开 PDF → 本文件实测 165 段落 / 34 张碎图 / **8 页（原 3 页）** / 正文 251 字**全乱码**。只适合有文字层的 PDF。
59. **`PDF.convert_pdf_to_img` 的 `save_dir` 必须已存在**：目录不存在时**既不报错也不生成文件**，下游 `insert_img` 才报 `No such file` —— 排查时容易误判成转图失败。
60. **`Docx.insert_img.scale` 是百分比，但换算系数随图片 DPI 变**：2287px 宽 @24% → 14.52cm；3370px 宽 @16% → 14.27cm。A4 纵向 + 默认页边距**可用宽 14.65cm**（左右各 3.17cm）。粗算 `cm ≈ px × scale × 0.000265`，落地前务必用 `wp:extent` 反算校验。
61. **`create_docx` 与 `open_docx` 返回形态不同**：`create_docx` 返回**元组** `(DocumentObject, path)`；`open_docx` 只返回 `DocumentObject`，别解包（会 `TypeError: cannot unpack non-iterable`）。
62. **裸调原子不走 pydantic**：无 `__info__` 时 `atomic_run` 直接调函数，枚举传字符串会崩（`'str' object has no attribute 'value'`）；放进流程里传小写字符串则正常（`model(**base_kwargs)` 会转换）。
63. **`$p:` 支持字符串拼接**：`inputList` 的 `value` 可以是片段数组，含 `p_var` 时引擎 `need_eval=True`，字面量转 `repr`、变量留裸名用 `+` 连起来（读 `executor/flow/params.py::_param_to_eval` 实证）。路径拼装不再需要额外参数。
64. **规格里的 Windows 路径必须收口**：手写/LLM 生成的规格极易出现 `F://a//b\c` 混合形态（本机实测 `F:\AI-Workbench\...` 被写成 `F://AI-Workbench//...\demo\pdf_pages`），落库后 `$p:` 与 Python 子流程全拿到坏路径 → `OCR 失败 F://...`。`load_spec()` 现在统一过 `norm_win_path()`：只处理 `X:` 开头路径，URL / UNC 原样放过。
65. **`element_relocator` 的 playwright 必须惰性导入**：`flow_generator` / `ai_flow` 只复用它的 `ServerDb`，顶层 `import playwright` 会让「没装浏览器」直接 `sys.exit(2)` 把整条链路干掉。改为 `_require_playwright()` 按需引入。
66. **`c_module` 按版本隔离**：执行器 `/api/robot/module/open` 带 `robotVersion=<发布版本>`。手工插的模块只有 `robot_version=0` → **本地真跑（设计态）成功、openapi 调用（发布态）报「该模块不存在」**（`robot_execute_record.result` 停在 `robotExecute`，openapi 侧只回 `5001 启动失败`）。发布接口不复制模块，`publish()` 已加 `clone_modules_for_version()`。
67. **`PDF.get_pdf_text` 的 `text_save_type` 决定成段质量**：`word` 一步出 docx，但**整页文字塞进一个段落**（换行变空格）；`txt` 保留换行，再经 `File.file_read` + `Docx.insert_docx` 才能**按行成段**。扫描件对它无效（返回 `['']`）。
68. **`Docx.create_docx(exist_handle_type=overwrite)` 只在「目标文件被占用」时失败**（2026-10-30 15:29 修正原结论）：原以为「文件已存在就必失败」，实测不是 —— 文件存在但没人打开时，`SaveAs` 能正常覆盖（刚跑 `PDF转Docx` 目标 494KB 被正常重写成 3 图版）。真因是 `word/core.py::handle_existence` 里 `os.remove` 被注释掉了，所以**目标被 Word/WPS/预览占用时没有「先删再建」这条退路**，COM 直接抛「Word 无法保存此文件，因为它已在别处打开」，又被 `create_docx` 的 `except` 吞成「**Word 文档读取失败，请检查文件是否损坏**」。**修法**：跑之前关掉占用它的程序（含 WorkBuddy 的文档预览面板）；批量场景加 `File.file_delete`（`on_error: "skip"`）前置节点，让「文件残留但没被占用」的情况干净重建。
69. **Bool / 数值字面量会被编译成字符串**（引擎 `params.py::_param_to_eval` 用 `f"{data}"`）：`visible_flag=False` → `'False'`（**非空字符串=真值**）→ Word 弹出一个可见的空白文档窗口；`underline_flag=0` → `'0'` → **整段加下划线**；`bold_flag=False` → 整段加粗。**修法：生成器 `_coerce_literals()` 把非 `Str/Any` 类型的 bool/int/float 字面量转成 `{"type":"python"}`**，编译出裸 `False`/`0`。

71. **目标 docx 被 Word/WPS/预览占用时，删也删不掉、建也建不了**：界面上只会看到「文件损坏」，真因在 `%APPDATA%/astron-rpa/logs/executor-*.log` 的 COM 错误里。模块里已加 `_clear_target()`，把这种情况翻译成「**目标 Word 正在被占用，请先关闭再运行**」。

78. **`path_invalid_msg` 类报错平台文案不统一**：同一种「文件不存在」，`File` 原子说「路径不存在」，`PDF` 原子说「填写文件路径有误，请输入正确的路径」，`Docx` 说「Word 文档读取失败，请检查文件是否损坏」。错误翻译层的规则表要按**原子**覆盖，不能只按一种说法。
79. **服务端地址以客户端 `conf.yaml` 为准**（用户 2026-10-30 指定）：设计器靠 `<安装目录>/resources/conf.yaml` 的 `remote_addr` 决定连哪个服务端，用户改这个文件来切换服务器。所以 `rpa_config` 的优先级改成 **环境变量 > conf.yaml > rpa_config.json > cookie 探测**，并且 `openapi.base` / `db.ssh_host` 一旦与 `gateway.host` 不同就**自动重算**（否则会出现「换了服务器还在拿旧地址调」——连得上但连错地方，极难发现）。安装目录靠三级定位：`RPA_CLIENT_CONF` → 常见安装位（`%ProgramFiles%` / 各盘 `Program Files\astron-rpa` 等）→ 运行中进程路径（`Get-Process astron-rpa`）。
80. **预检必须拼「目录 + 文件名」**：`Docx.create_docx(file_path=目录, file_name=名字)` 是拆开传的，只查目录会把「目标 docx 被 Word 打开着」这个最要命的情况漏掉（实测：只查目录时预检全绿，真跑第 2 步就报「文件损坏」）。`preflight._combo_target()` 现在按原子补扩展名拼成完整路径再查占用。
81. **WorkBuddy 的文档预览面板会独占文件**：`demo/20260914报废.docx` 被预览打开时 `probe_locked` 返回 True，流程必然失败；关掉预览就正常。排查时别只怀疑 Word/WPS 进程。
82. **PDF 细线是亚像素渲染的，按「连续暗像素」数会漏掉一半**：0.5px 的框线渲染成 255/248/236/255 明暗交替，用阈值 200 只抓到 3/14 条横线。**必须用「间隙容忍的游程」**（`gap=3`：暗像素之间允许隔 3 个亮点仍算同一条线），阈值抬到 `_LINE_TH=245` 才能稳定命中。
83. **扫描件的浅灰竖条纹会被当成表格边框**：原件有灰度 130~215 的竖向条带，宽松阈值下两张相邻的表被粘成一张、列数翻倍。**竖线/边界判定必须用严格阈值 `_STRICT_TH=120`**，横线才用 245 —— 两套阈值分工，不能共用一个。
84. **不能按词坐标聚类识别表格**：中文正文每行也有几十个词、x 分布连续，按 x 聚类会把整段正文判成表格（v1 三页报出 5 张假表）。表格只能**从页面图像的框线检测**得到，文字只用来填格。
85. **横线的 x 范围不能当分组条件**：合并单元格会让某条横线只画到半截（起点偏右/终点偏左），一旦要求「x 范围基本重合」，正常表格会被拆成多个碎片。判据只留「两条横线之间的纵向间距 + 该带内的竖线数量」。
86. **覆盖率阈值必须分横竖两套，且比直觉高得多**：`_h_covers` 取 `need=0.55`（真边框覆盖 1.0；被合并单元格里的文字压在线上时只有 0.2~0.4，取 0.12 会把「金额占比 0·46％」整列粘成一格）；`_v_rules` 取 `need=0.85`（汉字竖笔画只占行高 0.6~0.75，取 0.7 会把 9 列拆成 28 列）。**另外不要按「行带认可度」过滤列**——合并单元格多的表，内部竖线只在表头行出现，一过滤就全丢。
87. **合并单元格判定要用「文字行距」，不能用「是否垂直居中」**：真合并格里哪怕两行字也是正常行距（< 0.85×行高）；断线造成的假合并，两段文字分别贴两行、各自居中，间距接近一整行高。另：python-docx `merge` 报 `requested span not rectangular` 是因为先按「纵向合并 + 横向合并」两组列表分别 merge、矩形互相重叠——**必须先算互不重叠的单元格矩形再逐个合并**。
88. **字号标定不能用字形高度，要用「行宽 ÷ 字数」**：OCR 的 bbox 含上下留白，按高度算得 12.7pt（真实 10.8pt），整篇多出 2 页。正文行取 `n>=15` 字的行算 `行宽×pt/字数` 的中位数。
89. **分页符段落和表后空段会偷偷吃掉版面**：`add_paragraph()` + `add_break(PAGE)` 默认行距 23pt → 页尾少放一行、最后一句被挤成单独一页；表后默认空段同样多占 1.6cm。分别压到 `line_spacing=Pt(1)` 与 `Pt(4)`。
90. **大图 Windows OCR 会静默失败，必须分条带**：整页放大 2 倍 = 4574×6472 ≈ 3000 万像素 → 进程无 stdout/stderr、无输出文件，重试三次全空。切成 900px 高的条带（每带 800 万像素）稳定通过。**切点必须落在空白行上、条带之间不重叠**——重叠会让同一行被识别两次（「记录记录」「数数据据」），再补 `_dedupe_lines()` 按几何重叠去重兜底。
91. **`pf.create_robot()` 返回的是字符串 id，不是 dict**：`d.get("robotId")` 会 `AttributeError`。建机器人同名会报「存在同名机器人」，用 `find_robot()` 先查。
92. **自然语言匹配会被「长路径」污染**：`把 F:\…\星辰开源\demo\20260914报废_已转正.pdf 的第1到2页存到 …` 里路径贡献十几个 token，把「第1到2页」这个真意图淹掉 → 「抽取指定页」和「PDF合并」打平 0.50，被判「拿不准」。**算分前必须 `_strip_paths()` 抹掉路径**，但要把扩展名换成词（`.pdf`→`pdf`、`.xlsx`→`excel`），否则「PDF vs Word」这类区分也没了。
93. **页码话术是「参数级」硬证据，值得单独加分**：话里出现 `第1到2页` / `前3页` 时，给**有 `page_range` 参数**的规格 +0.25。词面相似度打不过长句，但参数层面能确定用户就是要抽页。
94. **从路径里剥「粘在后面的动词」不能一律切到最后一个分隔符**：`F:\demo\in里的pdf合成一个` 会被切成 `F:\demo`（丢了 `in`）。规则要按「最后一段有没有中文」分流：纯 ASCII 段原样保留；中英混排取开头的 ASCII 标识符（`pdf_merge_in里的pdf…` → `pdf_merge_in`）；纯中文段才回退到上一级。
95. **`intent_match` 的兜底不能返回 `excel_export`**：原来匹配不上就默认跑 Excel 导出，「帮我把这个 PDF 拆成两半」会**静默跑成一条完全不相干的流程，而且报 SUCCESS**。改成返回空串 → 打印现有流程清单 + 让用户改说法。**宁可说「没听懂」，也不能跑错还报成功。**
96. **预检报错文案里的路径带着中文括号尾巴**：`… 目录不存在：F:\x\y（父目录存在，流程不会自动建这一级）`，用 `rsplit("：")` 取到的不是纯路径，自愈层拿它去比参数值必然比不中（自愈静默不生效）。要用正则 `[A-Za-z]:[\\/][^（(，,、；;]*` 抽。
97. **`Code.ForList` 的结束标记是 `Code.ForEnd`，不是 `Code.ForListEnd`**（引擎 `flow/syntax/token.py::special_token_type_end`：`ForStep/ForList/ForDict/While` 全部以 `ForEnd` 收尾）。用错的话结束标记不会被识别成块结束，会被当普通原子编译成 `None(...)` 塞进循环体 → 运行时 `TypeError: 'NoneType' object is not callable`。编译产物里看到 `None(__skip_err__=...)` 就是这个病。
98. **`Script.module` 的 `module_param` 里要传循环变量，必须用 special 结构**：`{"rpa":"special","value":[{"type":"var","value":"item"}]}`。因为 `module_param` 是 `need_parse=json_str`，引擎只做 `json.loads` + `ComplexParamParser`，纯字符串永远是字面量。生成器已支持语法糖 `"$var:item"` / `"$p:out_dir"`（`flow_generator._json_refs`），规格里直接这么写即可。
99. **模块按机器人隔离，跨机器人引用 module_id 会得到 `None`**：`Script.module` 的 `content` 走 `package.module(module_id)`，查的是**当前流程**的 `process_info`；换个机器人引用别的机器人的模块 id → 查不到 → 返回 `(None, [])` → 报「无法导入模块 .None: No module named 'astron.None'」。**新机器人必须用 `make_module.py --robot <新id>` 重建一份**（模块内容一样，只是归属不同）。
100. **批量循环里不主动释放内存会 `MemoryError`**：`_ocr` 里的整页 PIL 位图 + numpy 灰度数组，单文件跑看不出来，循环几十次就爆（崩在 `crop.resize`）。修法：`_ocr` 结束 `im.close()`、`main` 每页 `del arr, d, res` + `gc.collect()`。
101. **关键词命中给分太粗（3 字以上直接 1.0），歧义词会把流程判错**：批量流程原来把「文件夹里」当关键词，结果「把这个文件夹里的PDF合并成一个」被判给批量流程（1.00 vs 合并 1.00 → 拿不准）。**批量词表要排除「文件夹 / 整个文件夹」这类歧义说法**——它们描述的是对象，不是「对每个文件做一遍」。
102. **用户说「都/全部/每个」时，单文件流程是「做不到」而不是「差一点」**：`match_spec_file()` 现在对批量话术做非对称加权 —— 带循环的规格 +0.2，不带的 **×0.6 降权**。这样「把这个文件夹的PDF都转成Word」稳定命中批量流程（1.00 vs 0.60），而「把这个文件夹里的PDF合并成一个」不受影响。
