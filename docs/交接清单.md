## 0. 交接规则（用户要求，永久默认）

用户会频繁更换 AI 接力开发。**每次收尾必须更新四件套**：`开发文档`（技术事实）、`开发进度.md`、`功能蓝图.md`、本清单。新会话**第一步读本清单**，禁止凭空上手。

### 0.1 标准交付流程（SOP，用户 2026-10-30 明确指定，**必须照此执行**）

```
用户发自然语言
   → AI 生成流程（选模板/写规格）
   → AI 自己校验好（结构校验 + 本地真跑，机器自检必须全绿）
   → 通知用户（附评审单）
   → 人工运行评审（设计器点「运行」）
   → 不通过：用户反馈 → AI 改规格 → 再验证（回到第 2 步）
   → 通过：用户说发布/调用（或授权 AI 自行处理）
```

**一条命令走完「生成→校验→落库→真跑→评审单」**：

```bash
python scripts/ai_flow.py --nl "把订单表导成新文件"        # 默认 review 阶段
python scripts/ai_flow.py --spec flows/xxx.json            # 用规格文件（改流程就是改它）
python scripts/ai_flow.py --nl "..." --stage draft         # 只生成校验，不落库
python scripts/ai_flow.py --spec flows/xxx.json --stage publish --version N   # 评审通过后发布
python scripts/ai_flow.py --spec flows/xxx.json --stage expose   # 发布 + 登记 openapi 可执行列表
python scripts/ai_flow.py --spec flows/xxx.json --stage invoke   # 用 API Key 真调用并验证产出
```

**一句话带参数**（`nl_params.py` 自动抽，见 §4 制品地图）：

```bash
# 源文件、输出目录、输出名、页码、缩放都能从话里抽出来
python scripts/ai_flow.py --nl "把 F:\demo\报废单.pdf 还原版面，另存成 最终版"
python scripts/ai_flow.py --nl "把 F:\demo\a.pdf 的第 1 到 2 页存到 F:\out"
python scripts/ai_flow.py --nl "转成word，放大25%"
# 批量意图（"整个文件夹都转"）默认拦下 —— 单文件流程只会处理一个，不偷偷漏
# 确实只想跑一个：加 --skip-batch-check
# 想全用规格默认值、忽略话里的值：加 --no-nl-params
```

> **用哪个 python**：流水线要 `requests`，本机用 `C:\Python314\python.exe`（或 Python311）。
> WorkBuddy 自带的 3.13 没装 requests，只能跑纯本地的探针脚本。

铁律四条：
1. **不许只生成不校验**——机器自检（`IS_PASS` + 本地真跑 `ExecuteStatus`）全绿才能通知用户。
2. **内容写进主流程**——设计器「编辑」默认打开主流程，写子流程用户看到空白。
3. **评审通过前不发布**——发布是对用户的承诺，必须等人工点头。
4. **`COMPLETED` 不等于做成了**——必须核对副作用（产出文件/内容）。实测踩过：主流程 v1 是空数组，openapi 执行 4 秒「运行成功」却什么都没干。

## 1. 项目一句话

**本项目是「AI 操作 RPA、生成 RPA 流程」的工具链**：用户说人话 → AI 生成固定流程 → 机器自检 → 人工评审 → 发布上线。**流程一旦搭好，就脱离 AI 独立运行**（设计器手动跑 / 平台定时任务 / openapi 接口调用，都不需要 AI 参与）。

AI 的角色只有两个：**生成流程**、**按反馈改流程**。AI 不是运行时的依赖。

### 1.1 定位红线（用户 2026-10-30 再次强调，写死）

| 是 | 不是 |
| --- | --- |
| 造「能把人话变成流程」的**生成能力** | 手搓一条条具体流程当交付物 |
| `flows/*.json` 是 AI 的**输出契约 + 模板库** | 人肉维护的流程仓库 |
| 流程产物在平台上独立运行 | 每次执行都要过一遍 AI |

**所以：不要自己钻具体业务细节、不要自作主张堆流程。** 遇到「现有原子做不到」的事，先说清边界和选项，由用户决定要不要扩；不是自己闷头造。

## 7. 可迁移性（插件形态）—— 2026-10-30 15:10 用户明确要求

> 原话：「当前方案预备做成可迁移方案 类似插件形式 换个全新环境要也能正确运行 服务器层面能不改就不改 改动多了迁移可能会出现问题」

> **「可迁移」的准确含义（2026-10-31 用户澄清）**：指**这套工具**（脚本 / 配置 / 流水线 / 技能包 / MCP）
> 换到新机器、新服务端能直接跑起来——**不是**要求 RPA 流程本身零元素。
> 流程里的**界面元素是目标机器人的资产**，换机器重新拾取一遍即可，流程规格一行都不用改。
> 所以「要不要用元素」不是取舍标准，**能不能用原子拼出来**才是。

### 7.1 原则

| 层级 | 做法 | 迁移成本 |
| --- | --- | --- |
| **L1 官方 HTTP API** | 建机器人 / 建流程 / 写 `process_content` / 写 `c_param` / 建模块 / 发布版本 / 登记 openapi / 触发执行 | 0 —— 换环境重放即可 |
| **L2 本地只读** | 读设计器 cookie 取会话、读 `%APPDATA%/astron` 编译产物、读本地日志、读 `docs/*.json` 快照 | 0 —— 跟着客户端走 |
| **L3 SQL 兜底（默认关闭）** | `c_module` 补丁、读 `robot_execute_record.execute_log`、元素库直读 | 有 —— 需要 SSH + MySQL 凭据，**默认 `db.enabled=false`** |

**硬性规定：新功能一律先问「能不能只用 L1+L2」。** L3 只允许出现在「官方接口确实没有」的场景，且必须能在关闭时降级。

### 7.2 已完成的改造（本轮）

1. **配置外置**：新增 `scripts/rpa_config.py` + `rpa_config.json`。原来散在 5 个文件里的
   服务端地址 / API Key / SSH 账号 / MySQL 密码 / 客户端 Python 路径全部收敛。
   优先级：**环境变量 `RPA_*` > 客户端 `conf.yaml` > `rpa_config.json` > cookie 探测 > 内置默认**。
2. **服务端以客户端为准**（用户 2026-10-30 指定）：设计器靠
   `<安装目录>/resources/conf.yaml` 的 `remote_addr` 决定连哪个服务端，用户改这个文件来
   切换服务器，所以工具链跟着它走。安装目录三级定位：`RPA_CLIENT_CONF` → 常见安装位
   （`%ProgramFiles%` / 各盘 `Program Files\astron-rpa`）→ 运行中进程路径
   （`Get-Process astron-rpa`）。`openapi.base` / `db.ssh_host` 与 `gateway.host` 不一致时
   **自动重算**——否则会出现「换了服务器还在拿旧地址调」，连得上但连错地方，极难发现。
3. **cookie 兜底**：找不到 conf.yaml 时，才从设计器 `.cookie.json` 的 host 列表取候选 →
   TCP 探测 → **只有恰好一个连得通才自动采用**；多个都通就报错并列出候选（宁可停下也不猜）。
4. **原子字典改走 API**：`load_atom_dict()` 优先调 `POST /api/robot/atom-new/all`
   （实测 357 个原子，`atomKey` + `atomContent` 齐全），失败退本地缓存
   `docs/atom_dict_cache.json`，最后才退 SQL。**这是摆脱数据库依赖的关键一步。**
5. **元素库降级**：`load_elements()` 在 `db.enabled=false` 时用 `docs/element_cache.json`
   缓存；无缓存就返回空字典（元素核对跳过，不阻塞结构校验）。
6. **发布不再写库**：`publish()` 改为**纯 API 校验**——发布后用
   `POST /api/robot/module/open` 带 `robotVersion=N` 验证模块是否在该版本
   （存在→`000000`，不存在→`700001`）。SQL 复制只在 `--repair-modules` 时启用。
7. **模块创建改走 API**：新增 `publish_flow.create_module()/save_module()/open_module()`。
   用官方接口建的模块 `creator_id` 是当前登录用户，**平台发布会自动复制到新版本**。
8. **环境自检**：新增 `scripts/doctor.py`，换环境第一条命令，逐项给结论和修法。

### 7.3 迁移到全新环境的步骤（照做即可）

```
1. 装 astron-rpa 设计器客户端，登录一次目标服务端      # 产生 .cookie.json
2. 改设计器 <安装目录>/resources/conf.yaml 的 remote_addr = 新服务端
   （**这一步决定连哪个服务端**，工具链自动跟随；不想改它就用 RPA_HOST 环境变量）
3. 拷贝整个项目目录（含 scripts/ flows/ docs/）
4. 改 rpa_config.json（只填 conf.yaml 给不了的东西）：
     openapi.api_key    = 新环境生成的 Key
     defaults.robot_id  = 新环境目标机器人 id
     db.enabled         = false（保持关闭，除非确实需要）
     gateway.host       = 留空即可（会被 conf.yaml 覆盖，留作兜底）
5. python scripts/rpa_config.py      # 确认 gateway.host 来源是「客户端 conf.yaml」
6. python scripts/doctor.py          # 逐项自检，红项按提示修
7. python scripts/ai_flow.py --spec flows/xxx.json --stage draft    # 只校验不落库
8. 建 Python 子流程模块（如需）：publish_flow.create_module(...) → 把返回的
   moduleId 写进对应规格的 `module_id` 参数默认值
9. python scripts/ai_flow.py --spec flows/xxx.json --stage review   # 落库+真跑+评审单
10. 人工评审通过后 --stage expose（发布+登记 openapi）→ --stage invoke（API 调用验证）
```

### 7.4 仍然「环境相关」、迁移时必须重建的东西

| 东西 | 为什么 | 怎么重建 |
| --- | --- | --- |
| 机器人 id / 流程 id | 每个环境自增生成 | `publish_flow.create_robot()` + `create_process()`，写回规格 |
| Python 子流程模块 id | 同上 | `create_module()`，写进规格 `module_id` 参数 |
| openapi API Key | 每个环境独立签发 | 平台「开放平台」生成后填 `rpa_config.json` |
| 设计器登录态 | cookie 按 host 存 | 新环境在设计器里登录一次 |
| 元素资产（uia/cv） | 元素按 robot 隔离，且是本机录制的 | 在设计器里对该 robot 重新拾取 |
| `docs/element_cache.json` | 是快照 | 换环境后用 `flow_generator.py --elements` 重新生成 |
