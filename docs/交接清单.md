## 0. 交接规则（用户要求，永久默认）

用户会频繁更换 AI 接力开发。**每次收尾必须更新四件套**：`开发文档`（技术事实）、`开发进度.md`、`功能蓝图.md`、本清单。新会话**第一步读本清单**，禁止凭空上手。

### 0.1 标准交付流程（SOP，用户 2026-10-30 明确指定，**必须照此执行**）

```
用户发自然语言
   → AI 生成流程（选模板/写规格）
   → AI 自己校验好（结构校验 + 本地真跑，机器自检必须全绿）
   → 通知用户（附评审单）
   → 人工运行评审（设计器点「运行」）
   → 不通过：用户反馈 → AI 改规格 → 再验证（回到第 2 步）
   → 通过：用户说发布/调用（或授权 AI 自行处理）
```

**一条命令走完「生成→校验→落库→真跑→评审单」**：

```bash
python scripts/ai_flow.py --nl "把订单表导成新文件"        # 默认 review 阶段
python scripts/ai_flow.py --spec flows/xxx.json            # 用规格文件（改流程就是改它）
python scripts/ai_flow.py --nl "..." --stage draft         # 只生成校验，不落库
python scripts/ai_flow.py --spec flows/xxx.json --stage publish --version N   # 评审通过后发布
python scripts/ai_flow.py --spec flows/xxx.json --stage expose   # 发布 + 登记 openapi 可执行列表
python scripts/ai_flow.py --spec flows/xxx.json --stage invoke   # 用 API Key 真调用并验证产出
```

**一句话带参数**（`nl_params.py` 自动抽，见 §4 制品地图）：

```bash
# 源文件、输出目录、输出名、页码、缩放都能从话里抽出来
python scripts/ai_flow.py --nl "把 F:\demo\报废单.pdf 还原版面，另存成 最终版"
python scripts/ai_flow.py --nl "把 F:\demo\a.pdf 的第 1 到 2 页存到 F:\out"
python scripts/ai_flow.py --nl "转成word，放大25%"
# 批量意图（"整个文件夹都转"）默认拦下 —— 单文件流程只会处理一个，不偷偷漏
# 确实只想跑一个：加 --skip-batch-check
# 想全用规格默认值、忽略话里的值：加 --no-nl-params
```

> **用哪个 python**：流水线要 `requests`，本机用 `C:\Python314\python.exe`（或 Python311）。
> WorkBuddy 自带的 3.13 没装 requests，只能跑纯本地的探针脚本。

铁律四条：
1. **不许只生成不校验**——机器自检（`IS_PASS` + 本地真跑 `ExecuteStatus`）全绿才能通知用户。
2. **内容写进主流程**——设计器「编辑」默认打开主流程，写子流程用户看到空白。
3. **评审通过前不发布**——发布是对用户的承诺，必须等人工点头。
4. **`COMPLETED` 不等于做成了**——必须核对副作用（产出文件/内容）。实测踩过：主流程 v1 是空数组，openapi 执行 4 秒「运行成功」却什么都没干。

## 1. 项目一句话

**本项目是「AI 操作 RPA、生成 RPA 流程」的工具链**：用户说人话 → AI 生成固定流程 → 机器自检 → 人工评审 → 发布上线。**流程一旦搭好，就脱离 AI 独立运行**（设计器手动跑 / 平台定时任务 / openapi 接口调用，都不需要 AI 参与）。

AI 的角色只有两个：**生成流程**、**按反馈改流程**。AI 不是运行时的依赖。

### 1.1 定位红线（用户 2026-10-30 再次强调，写死）

| 是 | 不是 |
| --- | --- |
| 造「能把人话变成流程」的**生成能力** | 手搓一条条具体流程当交付物 |
| `flows/*.json` 是 AI 的**输出契约 + 模板库** | 人肉维护的流程仓库 |
| 流程产物在平台上独立运行 | 每次执行都要过一遍 AI |

**所以：不要自己钻具体业务细节、不要自作主张堆流程。** 遇到「现有原子做不到」的事，先说清边界和选项，由用户决定要不要扩；不是自己闷头造。

### 1.2 L3 = 程序自己生成流程（2026-11-02 落地，入口 `scripts/nl2spec.py`）

**和 `ai_flow.py --nl` 不是一回事，别混**：

| | `ai_flow.py --nl` | `nl2spec.py` |
| --- | --- | --- |
| 干什么 | **关键词匹配已有规格**（`flows/` 里找最像的） | **LLM 现场生成新规格** |
| 能做没做过的事吗 | 不能 | 能 |
| 要 AI 会话在场吗 | 要 | **不要**，程序自己跑 |
| 失败怎么办 | 报「没听懂」 | 把 `spec_lint` 报错 / **引擎真实报错**回灌重写 |

```bash
python scripts/nl2spec.py "需求"                       # 生成 + 静态校验 → flows/gen_*.json
python scripts/nl2spec.py "需求" --verify --robot-name X  # 再加真跑闭环（推荐）
python scripts/nl2spec.py "需求" --set src_file=F:\real\a.xlsx  # 钉真实路径
python scripts/nl2spec.py --selftest                   # 离线自证（7/7，不需要 key）
```

**六条必须知道的事实**（都是 2026-11-02 实测出来的）：

1. **LLM 配置在 `rpa_config.json` 的 `llm` 段**（该文件不入库），也可用 `NL2SPEC_API_KEY/BASE/MODEL` 环境变量覆盖。任何 OpenAI 兼容 `/chat/completions` 都行。
2. **模型能力门槛真实存在**：`spark-x2.5-4b` 处理 9k token 的规格提示词 **240 秒超时**；`spark-x2.5` 也不稳。**`xopqwen36v35b` 3-8 秒稳定返回**，是当前可用项。换小模型别指望。
3. **`--verify` 不是可选项是必需项**：`spec_lint` 只能保证「结构合法」，管不了**参数语义**。实测 `Docx.convert_format` 的 `output_path` 要的是**目录**、`File.file_write` 的 `file_option` 默认 `error`（目标不存在直接报错）—— 这两条 lint 全绿、真跑才炸。
4. **原子参数陷阱表 `nl2spec.ATOM_HINTS`**：把实测踩到的「字典里看不出来的语义」写在生成期注入给模型，避免每次都靠真跑试错。**新发现一条就往里加**。
5. **~~已知边界~~ 已解决（2026-11-02 16:10）**：原先「正确解法是 `Script.module` 的需求会稳定失败」这条边界**不再成立**。现在 `nl2spec` 会自己判断原子能否表达，表达不了就写 Python 模块（判定表 `B-1~B-4`，见 `docs/流程规格DSL.md` §11）：
   - `--strategy auto`（默认）：原子优先，判「原子表达不了」→ 写脚本；
   - `--strategy atom`：只允许原子。**生成前先做可实现性评估**，判不可能就明确报「这个需求原子表达不了」并**以退出码 3 退出**——不硬拼假流程（旧版会拼 10 个节点、自愈 3 轮后报一句莫名的变量未定义）；
   - `--strategy script`：直接走脚本路线。
   实测「把 40 行销售明细按部门拆成多个 xlsx」：2 轮 / 13 秒 → 自动建模块注入 moduleId → 落库 → 真跑 SUCCESS → 4 文件 44 行、单号与源逐行一致。
   **但脚本节点的「参数可微调」仍有 1 个 P0 未闭合**（A17：`$p:` 被烘焙 → 设计器改参数不生效），详见 `docs/待办清单.md` 11c。
6. **`SUCCESS` 依旧不等于做对了**：真跑通过后必须核对产出文件。实测踩过「样本 docx 本身没有文字 → 产出 21 字节全是 `/`」，差点误判流程错。

## 3. 关键事实速查（防重复踩坑）

| 主题 | 事实 |
| --- | --- |
| **桌面元素可以自动拾取（不用人工录）** | `scripts/winelement_pick.py` 用**引擎自己的** `UIAElement(control).path()` 生成 elementData，再**自证**（喂给运行时 locator，比对 RuntimeId 是否同一控件），自证不过拒绝写库。`--window-self` 拾窗口本身（自证走 `WindowsCore.find`）。元素按 robotId 隔离，落库 `POST /api/robot/element/create` |
| **图像元素也可以自动拾取（CV）** | `scripts/cvelement_pick.py`：上传 PNG → 建 `type:"cv"` 元素 → **用引擎的 `CvCore.match_imgs` 自证**（命中框必须等于取图框）。注意 **CV 彩色目标有平台缺陷 A15**（灰度通道错位，匹配分被压到 0.92 < 阈值 0.95）→ 靶场/真实用例建议用**灰度**目标或把相似度调到 0.9 |
| **`Window.*` 走的不是 UIA locator** | `Window.exist/set_size/top/close` 走 `win32gui.FindWindow(cls, name)`，只读 `path[0]`；`WinEle.*` 才走 `locator.locator(pick["elementData"])`。拾窗口元素时 `path[0]` 必须有 `cls` + `name` |
| **`Window.exist` 是 IF 型原子（零副作用陷阱）** | 字典 `outputList` 为空、实现 `return bool` → 引擎编译成 `if Window().exist(...):` 并把**后续全部节点缩进进 if 体**。条件为假时整段被静默跳过、**流程仍报 SUCCESS**。判断依据只能是「后续节点确实产生了副作用」。同型原子：`CV.is_image_exist`、`File.exist` 等 |
| **`WinEle.get_element_text` 返回的是 Name 不是内容** | 实现是 `return locator.control().Name`（`winele.py:191-193`）。对 **Edit 控件 Name 是标签**（读到「计算机(C):」而不是用户输入）；对 **Button 控件 Name 就是文本**（能读到「帮助(H)」）。验证「填写」必须靠截图或外部读值 |
| **`Dialog.*` 只能从设计器点「运行」测** | 弹窗由「引擎 ↔ 设计器前端」的 **WebSocket** 通道渲染（`dialog/dialog.py:170` `ws.send_reply`）。本地无头执行：`--log_ws n` → **A12 直接 AttributeError**；`--log_ws y --wait-web-ws y` → 10 秒 `The websocket connection timed out` → CANCEL（设计器不会自动接管独立引擎实例）。另 **A13**：4 个弹窗原子用 `done.wait()` 无超时 → 前端不在线时**永久挂起** |
| **`Script.process` / `Script.module` 的参数填 processId 字符串** | 不是流程名！`module(id)` 查编译产物 `package.json` 的 `process_info`（键是 processId）→ 解析成 `processN` 模块名 → `importlib.import_module(".processN", package=...)` → 调 `main(args)`。`Script.process` 返回 kwargs 字典；`Script.module` 返回 `None`（生成的 `main()` 没 return） |
| **`need_parse` 参数必须给 JSON 字符串** | 字典标了 `need_parse` 的参数（`Dialog.select_box.options`、`Script.process.process_param`、`Script.module.module_param`…）在节点里必须写 `"$json:[...]"` 字符串，写 list → 编译期 `TypeError: the JSON object must be str...not list` |
| **`Script.module.module_param` 设计器打不开（2026-11-02 已修）** | 落库的 `module_param` 含 `{"rpa":"special",...}` 结构（含 `$p:`/`$var:` 引用），**设计器前端解析不了 → 一打开就「请求参数解析失败」**（引擎能跑）。`flow_generator.py` 已改：仅含 `$p:`（流程参数）的 `module_param` 在生成期**烘焙成默认值字面量**（纯 JSON 字符串，去掉 `rpa:special`/`$json:` 包裹），设计器可正常打开、引擎 `json.loads` 照常跑；**含 `$var:`（循环变量，如 `批量PDF版面还原`）的保持 `rpa:special`**（设计器无法显示，但引擎可跑，此类只能本地真跑验证）。已重落库 8 个 `$p:`-only 流程 |
| **mstsc 不是单实例** | 连开两个会得到两个同名同位置窗口，`FindWindow("#32770","远程桌面连接")` 命中哪个不确定 → 要用它当被拾取窗口，只能由外部预置**唯一**一个并 `SetWindowPos` 挪到固定位置 |

## 7. 可迁移性（插件形态）—— 2026-10-30 15:10 用户明确要求

> 原话：「当前方案预备做成可迁移方案 类似插件形式 换个全新环境要也能正确运行 服务器层面能不改就不改 改动多了迁移可能会出现问题」

> **「可迁移」的准确含义（2026-10-31 用户澄清）**：指**这套工具**（脚本 / 配置 / 流水线 / 技能包 / MCP）
> 换到新机器、新服务端能直接跑起来——**不是**要求 RPA 流程本身零元素。
> 流程里的**界面元素是目标机器人的资产**，换机器重新拾取一遍即可，流程规格一行都不用改。
> 所以「要不要用元素」不是取舍标准，**能不能用原子拼出来**才是。

### 7.1 原则

| 层级 | 做法 | 迁移成本 |
| --- | --- | --- |
| **L1 官方 HTTP API** | 建机器人 / 建流程 / 写 `process_content` / 写 `c_param` / 建模块 / 发布版本 / 登记 openapi / 触发执行 | 0 —— 换环境重放即可 |
| **L2 本地只读** | 读设计器 cookie 取会话、读 `%APPDATA%/astron` 编译产物、读本地日志、读 `docs/*.json` 快照 | 0 —— 跟着客户端走 |
| **L3 SQL 兜底（默认关闭）** | `c_module` 补丁、读 `robot_execute_record.execute_log`、元素库直读 | 有 —— 需要 SSH + MySQL 凭据，**默认 `db.enabled=false`** |

**硬性规定：新功能一律先问「能不能只用 L1+L2」。** L3 只允许出现在「官方接口确实没有」的场景，且必须能在关闭时降级。
