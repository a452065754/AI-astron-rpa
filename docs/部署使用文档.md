# 部署与使用文档

> 目标读者：要在**另一台电脑**上把这套工具跑起来的人。
> 读完这一篇就能从零到「跑通第一条流程」。

---

## 0. 先回答：这个项目是什么性质？

一句话：**它是外挂程序（旁路工具链），不是技能包，也不是 MCP。**

| 维度 | 结论 |
| --- | --- |
| **形态** | 一套独立的 Python 命令行工具（`scripts/`），通过 HTTP 接口操作已有的 Astron RPA 平台 |
| **运行位置** | 操作者自己的 Windows 电脑（要和设计器装在同一台） |
| **是否改服务端** | **不改**。不加插件、不改数据库、不重编镜像。服务端就是标准 Astron RPA |
| **是否 MCP** | ❌ 不是。没有实现 MCP server，不是给模型挂的工具协议端点 |
| **是否技能包** | ❌ 不是。技能包（skill）是给 AI 助手加载的提示+工具说明；这里是可直接 `python xxx.py` 跑的程序 |
| **交付物** | `flows/*.json`（流程规格）+ 平台里的「机器人 / 流程 / Python 模块」+ `docs/reviews/*.md`（评审单） |

### 它和这三者的关系（容易混，说清楚）

```
                    ┌─────────────────────────────┐
   自然语言  ──────▶ │  ai_flow.py（本项目，外挂）  │
                    └──────────┬──────────────────┘
                               │ HTTP（cookie / API Key）
                               ▼
                    ┌─────────────────────────────┐
                    │  Astron RPA 服务端（现成的） │
                    └──────────┬──────────────────┘
                               │ 本地网关 13159
                               ▼
                    ┌─────────────────────────────┐
                    │  设计器客户端（执行引擎）     │
                    └─────────────────────────────┘
```

- **不是技能包**：但**可以**包成技能——把这套命令写成 skill 的说明，AI 就能按需调用。本项目现在没做这层包装。
- **不是 MCP**：但**可以**加一层 MCP 包装（把 `--nl` / `--spec` 暴露成 MCP tools），让任何支持 MCP 的客户端调用。这是可选的扩展方向，当前未实现。
- **是外挂**：所有动作都走平台**已有的公开接口**（`/api/robot/*` 管理接口、`/api/rpa-openapi/*` 执行接口），相当于「用脚本代替人手点设计器」。

### 为什么必须装设计器客户端

不是因为它有界面，而是因为**两件事只有客户端能做**：

1. **登录态**：写流程要用你本人的会话 cookie（存在 `%APPDATA%\astron-rpa\.cookie.json`）。
2. **执行引擎**：真跑流程靠客户端起的本地网关（默认 `13159`）+ 内置 Python（`astronverse`）。

> 所以：**纯服务器环境跑不了本地真跑**，只能落库/发布/调用（走 openapi）。

## 1. 部署前准备

| 角色 | 需要什么 | 说明 |
| --- | --- | --- |
| **服务端** | 一套可用的 Astron RPA（docker compose） | 已有实例直接用；对外只需网关端口（本例 `32742`） |
| **客户端** | Astron RPA 设计器（Windows，Electron） | 装完要**登录一次**目标服务端 |
| **操作机** | Python 3.10+、`requests` | 就是装设计器的这台，不用另找机器 |
| **凭据** | openapi API Key | 平台「开放平台 / API 密钥」页生成（只有 `invoke` 阶段需要） |

> 本项目**不需要**：MySQL 直连、SSH、MinIO、Redis。那些只在排查故障时用（`db.enabled` 默认关）。

## 2. 部署步骤

### 2.1 第一步：装设计器并连对服务端

1. 装 Astron RPA 设计器（默认 `D:\Program Files\astron-rpa`）。
2. **改服务端地址**（这是唯一决定「连哪个服务器」的地方）：

```yaml
# <安装目录>\resources\conf.yaml
remote_addr: http://192.168.76.130:32742/
skip_engine_start: false
app_auth_type: casdoor
app_edition: saas
```

3. 启动设计器，用平台账号登录一次（之后 cookie 会缓存，脚本才能读写流程）。

### 2.2 第二步：准备操作机 Python

```bash
# 建议 3.10+（本机实测 3.14 / 3.11 都可以）
python -m pip install -r requirements.txt
```

> 注意：**流水线只需要 `requests`**。`paramiko`（SQL 兜底）、`playwright`（元素重定位）都是可选。
> 别用 WorkBuddy 自带的 3.13 跑流水线——它没装 `requests`。

### 2.3 第三步：拿代码 + 填配置

```bash
git clone https://github.com/a452065754/AI-astron-rpa.git
cd AI-astron-rpa

cp rpa_config.example.json rpa_config.json
```

编辑 `rpa_config.json`（**这个文件已在 `.gitignore`，不会入库**）：

```json
{
  "gateway": { "host": "192.168.76.130:32742", "scheme": "http" },
  "openapi": {
    "base": "http://192.168.76.130:32742/api/rpa-openapi",
    "api_key": "<平台生成的 Key>"
  },
  "client": { "python": "", "local_gateway_port": 13159 },
  "defaults": { "robot_id": "<你的机器人 id>" }
}
```

配置优先级：**环境变量 > 设计器 `conf.yaml` > `rpa_config.json` > cookie 探测 > 内置默认**。

也就是说：`gateway.host` 留空也行，会自动从 `conf.yaml` 的 `remote_addr` 推出来；`client.python` 留空会自动找设计器自带 Python。

### 2.4 第四步：环境自检（**换机器后第一条命令**）

```bash
python scripts/doctor.py
```

正常输出长这样（逐项 ✅ 才算就绪）：

```
 ✅ 客户端 conf.yaml    D:\Program Files\astron-rpa\resources\conf.yaml → remote_addr=192.168.76.130:32742
 ✅ 服务端地址            192.168.76.130:32742
 ✅ 客户端 Python       ...\AppData\Roaming\astron-rpa\python_core\python.exe
 ✅ 服务端可达            192.168.76.130:32742
 ✅ 设计器 cookie 文件    ...\astron-rpa\.cookie.json
 ✅ 登录态              cookie 里有 192.168.76.130:32742 的 SESSION
 ✅ 会话有效             当前用户 xyds037
 ✅ 设计接口             design-list 正常
 ✅ 设计器本地网关          127.0.0.1:13159 在线
 ✅ 目标机器人            2115990391806255104 流程 ['主流程']
 ✅ openapi          HTTP 200，已登记 4 个可执行流程
 ✅ 依赖 requests      已安装
```

**每一行都带修法**（`→` 后面那句）。常见红灯：

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 客户端 conf.yaml ❌ | 没装设计器 / 装到非默认路径 | 设 `RPA_CLIENT_CONF` 指向 conf.yaml |
| 登录态 ❌ | 没登录过 / 连的不是这个服务端 | 打开设计器登录一次 |
| 本地网关 ⚠️ | 设计器没启动 | 启动设计器（只是本地真跑不了，落库仍可） |
| 目标机器人 ❌ | robot_id 不对 / 该机器人没「主流程」 | 改 `defaults.robot_id`，或在设计器里建一个 |

## 3. 跑通第一条流程（验收）

挑一条零依赖的（Excel 拆表），不需要元素、不需要额外模块：

```bash
# 1) 只看生成+校验，不落库不执行（最安全）
python scripts/ai_flow.py --spec flows/Excel按条件拆表小流程.json --stage draft

# 2) 完整链路：校验 → 预检 → 落库 → 本地真跑 → 出评审单
python scripts/ai_flow.py --spec flows/Excel按条件拆表小流程.json --robot-id <你的 robotId>
```

预期看到：

```
[3/6] IS_PASS: YES ✅（错误 0 / 警告 0）
[3.5] 预检 通过 ✅（error 0 / warn 0）
[4/6] 写入机器人主流程... 回读一致=True
[5/6] SUCCESS ✅（3.0s）
      新建：['拆分_研发.xlsx', '拆分_销售.xlsx', '拆分_人事.xlsx']
[6/6] 评审单：docs/reviews/2026xxxx_Excel按条件拆表小流程.md
```

然后打开设计器 → 该机器人 → 「编辑」→ 顶部「运行」，人工确认输入输出对不对。

> 也可以用自然语言：
> ```bash
> python scripts/ai_flow.py --nl "把这张表按部门拆成多个文件"
> ```
> 会自动匹配已有规格并抽取参数（源文件路径、页码、输出名等）。

## 4. 换到另一台电脑，到底要改什么

**服务端不用动**（除非也换服务器）。操作机这边只有 5 处：

| # | 要改的 | 怎么改 |
| --- | --- | --- |
| 1 | 设计器的服务端地址 | `<安装目录>\resources\conf.yaml` 的 `remote_addr` |
| 2 | API Key | `rpa_config.json` 的 `openapi.api_key`（Key 跟环境绑定，换环境要重发） |
| 3 | 机器人 id | `rpa_config.json` 的 `defaults.robot_id` |
| 4 | **Python 子流程模块 id** | **必须重建**（模块按机器人隔离，见下） |
| 5 | 规格里的绝对路径 | 一般不用手改：`nl_params.rebase_paths()` 会按文件名在项目里找回 |

### 第 4 条最容易踩坑：模块按机器人隔离

`Script.module` 节点引用的是 `module_id`，而模块**属于某个机器人**。跨机器人引用会得到 `None`，报「无法导入模块 .None」。

```bash
# 建机器人 + 上传模块 + 把新 module_id 写回规格，一条命令搞定
python scripts/make_module.py \
  --py scripts/mod_excel_split.py \
  --new-robot "Excel按条件拆表" \
  --name "Excel拆表" \
  --spec flows/Excel按条件拆表小流程.json
```

输出会打印新的 `robot_id` 和 `module_id`，规格里的 `module_id` 参数已自动更新。

### 迁移后自检顺序

```
python scripts/doctor.py                      # 1. 环境
python scripts/ai_flow.py --spec <规格> --stage draft   # 2. 结构与元素
python scripts/ai_flow.py --spec <规格> --robot-id <新id>  # 3. 真跑
```

## 5. 命令速查

| 命令 | 作用 |
| --- | --- |
| `python scripts/doctor.py` | 环境自检（只读，逐项给修法） |
| `python scripts/atom_catalog.py` | 查可用原子（按域/关键词/单个，带必填参数与枚举） |
| `python scripts/spec_lint.py flows/x.json` | 校验流程规格，报错带「第几个节点 + 怎么改」 |
| `python scripts/ai_flow.py --nl "..."` | 自然语言 → 匹配规格 → 抽参数 → 全链路 |
| `python scripts/ai_flow.py --spec flows/x.json` | 按规格跑全链路（默认 review 阶段） |
| `--stage draft` | 只生成+校验，不落库不执行 |
| `--stage publish --version N` | 发布机器人版本（人工评审通过后用） |
| `--stage expose` | 发布 + 登记 openapi 可执行列表 |
| `--stage invoke --params '{...}'` | 用 API Key 触发执行（跑已发布版本） |
| `--no-run` | 跳过本地真跑 |
| `--skip-preflight` | 跳过运行前预检 |
| `--skip-batch-check` | 批量意图也继续（默认拦下） |
| `python scripts/make_module.py --py x.py --robot <id>` | 上传/更新 Python 子流程模块 |
| `python scripts/run_flow_local.py --robot-id <id>` | 只跑一遍（调试用） |

## 6. 常见问题

**Q1：设计器里第一次点开「Python 子流程」节点，弹一次错，刷新就好了？**
正常现象，不是缺陷。客户端首次为该机器人编译 `venvs\<robot_id>\astron\main.py` 时，设计器在编译落盘前就去读取渲染。缓存后即正常。**所有用 `Script.module` 的流程都会这样**。

**Q2：报「本地网关 127.0.0.1:13159 未监听」？**
设计器没启动。启动客户端即可；如果只想落库不真跑，加 `--no-run`。

**Q3：报「找不到设计器 cookie 文件」？**
打开设计器登录一次。cookie 在 `%APPDATA%\astron-rpa\.cookie.json`。

**Q4：报「无法导入模块 .None」？**
模块按机器人隔离，跨机器人引用了别人的 `module_id`。用 `make_module.py --robot <目标id>` 重建。

**Q5：网页类流程报元素找不到？**
元素资产按机器人隔离，必须在设计器里对**这个**机器人「拾取元素」一次。
这不是「不可迁移」——**可迁移指的是这套工具**（脚本、配置、流水线换机器直接能跑）；
流程里的元素属于目标机器人的资产，换机器重新拾取一遍即可，流程规格不用改。

**Q6：说「把这个文件夹的 PDF 都转成 Word」被拦下了？**
单文件流程只处理一个文件，检测到批量意图会主动拦下（避免偷偷漏文件）。批量请用 `批量PDF版面还原小流程`。

**Q7：本机 Python 跑不起来？**
流水线只要 `requests`。若用 WorkBuddy 自带 3.13 会缺包，换系统 Python（3.10+）。

## 7. 安全提示

- `rpa_config.json`、`docs/_local_secrets.md` 含真实凭据，**已在 `.gitignore`，不要提交**。
- 仓库文档里的凭据都是占位符（`<RPA_API_KEY>` 等），真实值以本机 `rpa_config.json` 为准。
- API Key 与环境绑定：换环境要重新签发，旧 Key 建议在控制台吊销。
